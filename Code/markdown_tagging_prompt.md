# Markdown 加標籤功能：開發指令

請針對 `D:\桌面\完整財報分析器` 規劃並實作 Markdown 加標籤功能，供後續階層追蹤及切塊使用。

先閱讀 `AGENTS.md`、`USER_STORIES.md`、`FLOWCHART.md` 與 `Code/README.md`，再檢查目前的 Markdown 處理結果與程式。最終預計處理約 100–200 份完整財報書。

## 一、已確認的階層規則

採用舊程式的堆疊追蹤概念，但階層來源分成兩部分：

**固定的前兩層：**

- 第 1 層：目錄大標，例如「合併財務報告附註」。
- 第 2 層：目錄小標，例如「一、公司沿革」。
- 這兩層必須根據目錄實際列出的項目與父子關係定義，再對應正文位置，不能只依正文編號或 Markdown 的 `#` 數量推斷。
- 目錄項目與正文對應不明確時，標示待確認，不編造或強行配對。

**第 2 層之下的小標題：**

- 依標題編號「類型首次出現的順序」，動態分配層級。
- 每進入新的目錄小標，清空上一個目錄小標底下的類型對應與小標題堆疊。
- 第一種遇到的類型，分配至整份結構的第 3 層；第二種新類型分配至第 4 層，依序往下。
- 再遇到已知類型，回到它在目前目錄小標範圍內已分配的層級。
- 更新某層標題時，移除該層原標題及其下層的目前路徑，但保留此範圍已建立的類型對應。
- 進入新的目錄大標時，清除原目錄小標與全部下層狀態。
- 已辨識為目錄大標、小標的文字，不可再重複當成動態小標題。
- 內文與表格繼承目前有效的完整標題路徑。

示例：

```text
第1層：合併財務報告附註
  第2層：四、重大會計政策
    第3層：(一) 金融工具       ← 此範圍第一種編號類型
      第4層：1. 金融資產       ← 第二種編號類型
      第4層：2. 金融負債       ← 同類型，替換同層標題
    第3層：(二) 存貨           ← 回到已知類型，清除下層目前路徑

  第2層：五、重大會計判斷      ← 重置動態對應
    第3層：1. 判斷事項         ← 新範圍首先遇到 1.，因此是第3層
      第4層：(1) 衡量方式
```

## 二、標籤需要記錄的資訊

- 目錄大標。
- 目錄小標。
- 其他小標題的類型、動態層級及完整父子路徑。
- 來源頁數。
- 財報年份。
- 公司名稱。
- 股票代號，與公司名稱分開保存。
- 主要會計項目：本次不實作，不自行抽取或推定。

頁數必須區分 PDF 實體頁序與文件印刷頁碼，不能以 Markdown 行號代替。年份必須區分文件所屬期間與正文／表格中的比較年度。來源不明的欄位保持未知，不自行補造。

上述欄位的具體來源、標籤語法及跨頁表示方式若尚未確認，先提出精簡方案問我。

## 三、與既有標題補抓功能的銜接

先閱讀實際程式，確認上一階段是否已實作，不假設已完成。

先前確認的補抓規則為：

- 原有 Markdown 標題保持原樣。
- HTML `<table>...</table>` 內不做標題補抓。
- 同一行依指定編號形式辨識候選，不跨行合併、不依空白拆分。
- 編號後文字去除頭尾空白，空白或超過 20 字元就排除。
- 通過字數檢查後，行尾為 `:` 或 `：` 的候選加單一 `#`，留待另外處理。
- 其餘依已確認標點排除規則判斷，通過者加 `##`。

**單一 `#` 的冒號候選不代表已確認的一般標題，不能直接加入動態階層。** 原有 `#` 與後加的特殊候選若無法區分，先詢問如何識別，不自行猜測。

本次加標籤階段不以 `#` 數量直接決定階層。無編號標題、額外編號類型或類型辨識不清的處理，先問我。

表格內容仍須保持原樣；若需表格邊界標記或來源資訊，先確認採用表格外標記或其他方式，不修改儲存格內容。目錄即使是 HTML 表格，也可讀取以取得大標、小標，但不改寫原表格。

## 四、可參考的舊程式

參考資料位於：

`D:\桌面\完整財報分析器\Reference Sources\Financial_RAG_Core\Function\`

請閱讀：

- `markdown_title.py`：舊版標題類型辨識、自訂標題標籤與內文標記。
- `markdown_table_tagger.py`：表格邊界與附近章節資訊的追蹤。
- `chunk_parser.py`：將標籤解析成標題、內文、表格及頁序區塊。
- `chunk_hierarchy.py`：維護標題堆疊與父層路徑，回到同層或上層時清除下層。

沿用其可理解、可追溯的處理概念，不直接搬用全部舊規則：

- 舊版將編號類型固定對應至 `<hd2>`、`<hd3>` 等；本次依前述「前兩層固定、後續動態」規格實作。
- 邏輯層級與實際標籤名稱分開考慮，不因舊標籤叫 `<hd2>` 就直接認定它是本次第 2 層。
- 舊版 `<hd9>`、`<hd10>` 有特殊用途，不自行套用。
- 舊表格偵測針對 `|` 表格，必須核對目前 Docling HTML 表格格式。
- 不沿用先清除全部 Markdown 標題符號的做法。
- 保留參考資料原貌，本專案改寫一律放在 `Code/`。

## 六、驗證與交付

驗證至少包括：

- 目錄大標與小標固定為第 1、2 層。
- 不同目錄小標可有不同的類型與層級對應。
- 新類型往下建立層級，已知類型回到原層。
- 回到同層或上層後，不殘留舊的下層路徑。
- 更換目錄小標、大標時正確重置。
- 內文與表格繼承正確路徑，表格內容保持不變。
- 未知 metadata 不被補造，頁序不被混淆。
- 重複執行不產生重複標籤。

用繁體中文交付修改摘要、檔案位置、執行方式、驗證結果、限制與待確認事項。結構測試通過不代表真實目錄與標題辨識品質通過。

有任何不確定的地方先問我，不自行決定。
