# Markdown 加標籤實作方案（待使用者確認）

依使用者附件 markdown_tagging_prompt.md 規劃，尚未實作加標籤或改寫既有產物。已閱讀既有規則1.1、補標記修改紀錄，以及參考 markdown_title.py、markdown_table_tagger.py、chunk_parser.py、chunk_hierarchy.py。舊程式固定hd層級、管線表格、年份猜測與內文strip流程不直接採用。

## 已確認需求

目錄大標／小標是邏輯1／2層，必須由目錄與正文對應建立。第2層以下按編號類型首次出現順序分配3層起；回到已知類型清除同層及以下目前標題但保留類型對應。換小標重置動態狀態，換大標清除全部下層。表格與內文繼承有效路徑，不改表格原文。冒號補抓候選不進動態階層。未知metadata不猜，不實作主要會計項目、chunk、正文JSON、embedding或問答。

## 建議方案（全部待確認）

1. 本機標準庫HTML解析器讀取目錄表格，產生候選目錄樹；比對用文字可移除編號／空白，但保留原文及證據。只接受唯一可核對對應，彙總項目、同名、OCR差異或無正文位置時標示待確認，不做模糊強配。先對完整文件標籤，不刪前段，附註外可標為範圍外／未配對。使用者需核對候選目錄樹與配對，不以成功執行代表目錄品質通過。
2. 動態標題只辨識既有Markdown標題行，沿用已確認四類編號／成對括號／半形一至兩位數字及略過列表連字號。井號數量不決定層級。以同次processed manifest中的colon_review辨識冒號候選，核對來源／輸出雜湊；紀錄缺失或不符不能可靠分辨時標為待確認。無編號且非目錄對應標題、其他類型亦不擅自分配層級；未知邊界後的路徑要標示不確定，避免默默歸入舊章節。
3. 建議以獨立HTML註解作開始／結束標籤，記錄block類型、邏輯層級、編號類型、父子路徑、metadata及狀態，原Markdown行不改。表格標籤只放table外；標題、表格、空行、頁序變更為區塊邊界，跨頁分開區塊但保留階層。標籤只是Markdown註解metadata，不另輸出正文JSON或chunk。具體註解鍵名與版本集中設定；必須可識別本功能標籤以支援重複執行。
4. 本輪不從比較年度推定報告年份，也不從檔名自動宣稱公司或代號。使用者提供明確metadata才填，否則unknown並記來源。只把PDF_PAGE明確標記當PDF實體頁序；獨立數字頁碼行只能作印刷頁碼候選，不擅自認為是PDF頁序。目前指定raw來源沒有PDF_PAGE，實體頁序保持未知，不為補此欄重跑PDF。
5. 新增選單4／--tag-markdown讀取既有processed的document.md及相鄰manifest，不必重跑PDF或補抓。輸出markdown_tagged/來源相對路徑去副檔名/tagging_台北時間/，包含document.md與manifest執行紀錄／待確認清單，不覆寫前階段；export_enabled可停用。先用先前指定文件的最新規則1.1結果測試。
