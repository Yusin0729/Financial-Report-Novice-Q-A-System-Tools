# Financial RAG 操作說明

適用版本：2026-10-29。對象：第一次接觸本專案的使用者。

本系統可將 PDF 財報轉成可檢索的資料，建立向量索引，再依問題找出證據、重新排序並產生回答。建庫完成後，同一份資料可以重複查詢。

## 1. 先選擇使用方式

| 使用方式 | 適合情況 | 操作介面 |
| --- | --- | --- |
| Windows 本機 | 想使用完整網站介面，查看資料、問答及實驗報告 | 瀏覽器網站 |
| Google Colab | 想用雲端 GPU 執行本機 BGE 模型或前處理 | Notebook 逐格執行 |

目前 Colab Notebook 提供階段範圍執行、建庫及單題本機重排序範例；完整網站的所有互動功能尚未包成 Colab 網站。真實 Colab GPU 安裝及推論仍待環境驗證。

程式位置：[GitHub 儲存庫](https://github.com/Yusin0729/Financial-Report-Novice-Q-A-System-Tools)。

## 2. 最快開始的三條路徑

| 手上已有的資料 | 要做的事 |
| --- | --- |
| 原始財報 PDF | 放入來源資料夾，依序執行階段1→5，再開始查詢 |
| 本系統產生的第四階段 chunk JSON | 放回原有批次結構，執行階段5建庫，再開始查詢 |
| 完整且相容的既有向量資料庫 | 在「問答系統」選取索引後查詢；跨電腦／系統移植須先核對可用性 |

第一次使用建議先選一份財報、使用 BGE 建庫並做「只排序」，確認能找到資料，再加入重排序和 LLM 回答。

## 3. 第一次取得程式

1. 開啟 GitHub 儲存庫，按 **Code → Download ZIP**。
2. 將 ZIP 完整解壓縮，例如放在 `D:\Financial_RAG`。
3. 專案根目錄應同時看得到 `Code`、`Code_2`、`colab`、`AGENTS.md`、`start-web.cmd`。

GitHub 只包含程式與文件。財報、已建索引、測試集、問題向量題庫、API 金鑰、虛擬環境與模型快取需要另外準備。下載程式後不會自動出現原作者的資料。

### 3.1 Windows 首次安裝

已經由提供者安裝好環境的電腦可以直接跳到第4節。換一台電腦時，請重新建立環境，不要直接搬動別人的 `.venv` 資料夾。

目前 Windows 環境使用 Python 3.11，並分為兩個環境：

| 路徑 | 用途 |
| --- | --- |
| `Code/.venv_pdf` | 階段1～4：PDF、Markdown、標籤、chunk |
| `Code/.venv` | 階段5建庫、網站、檢索、重排序與回答 |

安裝 Python 3.11 後，在專案根目錄開啟 PowerShell。以下以 `D:\Financial_RAG` 為例：

```powershell
Set-Location D:\Financial_RAG
py -3.11 -m venv Code/.venv_pdf
py -3.11 -m venv Code/.venv
```

安裝目前 Windows 環境的套件快照：

```powershell
& .\Code\.venv_pdf\Scripts\python.exe -m pip install -r Code/requirements.pdf.lock --only-binary=:all:
& .\Code\.venv\Scripts\python.exe -m pip install -r Code_2/requirements.lock
& .\Code\.venv\Scripts\python.exe -m pip install -r Code_2/requirements.txt
```

安裝可能需要一段時間，第一次使用 BGE／Docling 也可能下載模型。這些是現有環境的版本快照，其他電腦的安裝相容性仍須實際核對；如出現版本衝突，保留錯誤訊息交給維護者，不要隨意替換模型或刪除資料。

Colab 使用自己的安裝格；不要在 Colab 套用上述 Windows lock 檔。

## 4. 開啟本機網站

1. 在專案根目錄雙擊 `start-web.cmd`。
2. 等待瀏覽器開啟，預設網址為 `http://127.0.0.1:8765/`。
3. 檢查畫面顯示本機服務已連線。

也可在專案根目錄執行：

```powershell
& .\Code\.venv\Scripts\python.exe -X utf8 -m Code_2.gui --open-browser
```

網站執行時請保持後端程序開啟。要結束時，先等工作完成，再按網站的「關閉服務」。建庫中不要直接關閉後端程序。

### 4.1 側邊選單

| 選單 | 可以做什麼 |
| --- | --- |
| 前處理 | 選來源、執行階段1～4，或設定連續階段範圍 |
| 向量資料庫 | 第五階段建庫、查看內容、篩選與刪除索引資料 |
| 問答系統 | 單題檢索、重排序、回答，以及 Excel 批次實驗 |

## 5. 設定 API 金鑰

打開「API 金鑰」，依用途填入並保存：

| 用途 | 可用方式 | 是否需要金鑰 |
| --- | --- | --- |
| Embedding／向量化 | 本機 BGE-M3 | 不需要 API key |
| Embedding／向量化 | Voyage | 需要 Voyage key |
| 重排序 | 本機 BGE reranker | 不需要 API key |
| 重排序 | Voyage | 需要 Voyage key |
| LLM 回答 | Gemini 或 GPT | 需要對應供應商 key |

API key 不代表模型名稱，使用 Gemini／GPT 時仍須指定模型。系統預設回答模型為 `gemini-3.1-flash-lite`，實際可否呼叫以該帳號的 API 權限為準。

金鑰設定可刪除；刪除後，依賴該設定的 API 功能需要重新選擇有效設定。不要把 key 貼進問題、Excel、GitHub 或分享的報告。

Voyage 與 LLM 的費用由供應商計算；Colab GPU 不會降低這些 API 的 token 用量。重複問題命中題庫可省掉重新產生問題向量，但重排序與回答仍可能需要 API 用量。

## 6. 放入財報與階段產物

來源 PDF 放在專案的 `Financial Statements/`，可依股票代號分子資料夾。檔名須能辨識年度與股號，例如：

```text
Financial_RAG/
  Financial Statements/
    2330/
      2024Q4_2330_Financial_Report.pdf
```

使用系統既有的中間產物時，保留批次資料夾和檔名；不要只把檔案散放在 `Output` 根目錄。

```text
Output/
  markdown_raw/        # 階段1產物；供階段2讀取
  markdown_processed/  # 階段2產物；供階段3讀取
  markdown_tagged/     # 階段3產物；供階段4讀取
  markdown_chunk/      # 階段4產物；供階段5讀取
```

每個目錄下面會有以 `Financial_...` 命名的批次。若來源清單看不到檔案，先確認是否放在正確目錄、保留原批次結構，並按「更新清單」。

## 7. 執行前處理與建庫

### 7.1 五個階段

| 階段 | 輸入 | 主要工作 | 主要產物 |
| --- | --- | --- | --- |
| 1 | 財報 PDF | 抽取文字、辨識表格、轉為 Markdown | raw Markdown與紀錄 |
| 2 | raw Markdown | 整理標題、空白與頁碼等內容 | processed Markdown |
| 3 | processed Markdown | 標記章節、內容及表格邊界 | tagged Markdown |
| 4 | tagged Markdown | 依切法與脈絡模式產生 chunk | chunk JSON／Markdown |
| 5 | chunk JSON | 記憶體前處理、embedding、寫入 Chroma | 向量索引及建庫紀錄 |

階段5不另輸出 prepared JSON／Markdown。它會顯示各文件成功或失敗。

### 7.2 單階段操作

1. 選擇階段。
2. 勾選資料夾或個別檔案。
3. 調整本階段設定。
4. 按執行，查看目前檔案、進度與結果。
5. 確認成功後再使用產物；部分失敗時查看對應紀錄。

### 7.3 連續執行，例如階段2→5

1. 在「執行範圍」將起始設為2、結束設為5。
2. 勾選階段2的來源，也就是既有 raw Markdown。
3. 設定第四階段切法及第五階段建庫模型／索引名稱。
4. 按「連續執行」。系統只銜接本次產生的對應檔案；階段失敗後會停止後續處理。

可勾選「只保留最終階段產物」：

- 全部成功後，清理本次中間產物，保留 Record 執行紀錄。
- 失敗或取消時保留中間檔，方便查錯。
- 不會刪除原始來源或以前的批次。
- 結束於階段5時，最後保留向量索引及建庫紀錄；不會保留本次中間 chunk 檔。

**若之後要使用「舊報告重排序」，建議保留 chunk JSON。** 該功能可能需要來源 chunk 檔還原完整候選；即使向量索引還在，清理來源檔也可能影響舊報告重排。

### 7.4 第四階段主要設定

| 設定 | 說明 |
| --- | --- |
| 原本切法 `original` | 文字依門檻累積，在完整 content 結束處切；保留 hd2 邊界，可能超過設定字數 |
| 父子切法 `parent_child` | 同完整標題路徑的相鄰內文先合併，超過門檻再切子項；命中子項可帶回完整必回父項 |
| 字數門檻 | 例如250或700，會影響產物名稱及索引分組；不是 token 數 |
| 文字 embedding 脈絡 | 純正文／正文＋說明／正文＋小標、小標題及說明 |
| 表格 embedding 脈絡 | 純表格／表格＋說明／表格＋小標、小標題及說明 |

文字與表格可分開設定，共9種組合。完整脈絡不額外把年度、股號、Main_Section 加入向量文字；原文本來出現的年度仍保留。這些資料仍可存於 metadata，供來源追蹤及篩選。

跨頁表格、`###` 特殊群組另有規則；不能把所有 chunk 都視為嚴格固定字數。原始切法也可能有跨頁表格等必回關係。

### 7.5 第五階段：建立索引

1. 打開「向量資料庫」。
2. 選擇第四階段 chunk JSON。
3. 選 BGE-M3 或 Voyage，並選擇新建索引、批次建立或加入既有索引。
4. 新建時填入容易辨識的名稱，例如 `2024_BGE_父子250_文字正文_表格完整`。
5. Voyage 需選有效金鑰設定並明確啟用 API；BGE 第一次可能下載權重。
6. 開始建庫，確認各文件的完成狀態。

| 索引操作 | 適用情況 |
| --- | --- |
| 新建索引 | 想保存一份獨立實驗，即使設定相同也分開存 |
| 批次建立獨立索引 | 一次勾多種切法／標籤組合，自動分組並依序建立 |
| 加入既有索引 | 新資料與該索引的模型、切法、字數、標籤及版本相容 |

不同 embedding 模型不能混用問題向量；切分或脈絡不同時也應選對應索引。改了 chunk 文字後，不會自動改寫舊向量，需重新建庫或建立新索引。

建庫中如要停止，使用畫面的「結束工作／結束位置」。系統在安全文件邊界停止，不應直接強制關閉程序。

## 8. 查詢與問答

1. 打開「問答系統」。
2. 選 embedding 模型、切分模式與已建好的索引。
3. 輸入問題。
4. 需要時設定股號／內容年度篩選；沒有要求時可留空。
5. 選執行模式，設定召回與保留數量，再開始查詢。

| 模式 | 會執行什麼 | 適合用途 |
| --- | --- | --- |
| 只排序 | 將問題向量化，找出相似 chunk | 先確認索引能否找到證據 |
| 重排序 | 先檢索，再用所選 reranker 重新排序 | 比較候選是否更早出現 |
| 完整回答 | 檢索、可選重排序，再交給 Gemini／GPT | 取得附證據的文字答案 |

目前預設召回50筆、保留10筆。可選多個索引依序獨立跑，結果分開比較，不把多組索引混成同一排名。

保留證據時先選命中子項，再帶回需要的父項；相同父項去重且不往後補選，所以保留10個子項不一定得到10組最終證據。「額外帶回標題父項」是另一個可選設定，原始切法不適用。

完整回答選Gemini時，可在開始查詢按鈕上方的「Gemini 回答指令」修改指令，並儲存在目前瀏覽器。LLM直接輸出文字／Markdown，不再要求固定JSON或程式計算規格。

### 8.1 如何看結果

- **結果摘要**：答案或目前完成階段，以及是否缺少證據。
- **召回片段**：初步檢索排名、chunk 與來源。
- **重排序**：重排後的排名與分數。
- **用量與設定**：模型、時間、用量及快取等資訊。

答案附來源不代表內容必然正確。計算由LLM直接完成，程式不驗算。使用者仍需核對年度欄、幣別、單位和運算資料；證據不足時，系統應列出缺少內容。

一般單題操作目前不另外產生 Excel 批次測報。需要大量比較及保存逐題實驗結果時，使用下一節的 Excel 批次功能。

### 8.2 找不到索引

主清單目前優先顯示先前指定的 BGE父子250 G3、Voyage原始 G2；其他索引放在預設收合的「歷史索引」。新使用者新建的索引也可能出現在歷史清單，請展開查看。

如果清單完全沒有索引，先確認第五階段已完成，並且所選模型／切分模式符合索引設定。

## 9. Excel 批次測試與報告（實驗功能）

### 9.1 上傳題目

在問答系統將「輸入方式」改成「Excel 批次測試」，上傳 `.xlsx`，選工作表，再勾選要跑的題目。

| 欄位 | 用途 |
| --- | --- |
| `ID`、`Question` | 必填，題號及問題 |
| `Years` | 可選內容年度篩選，多年度任一年符合即可先召回 |
| `Doc_Id` | 可選，提取股號作篩選 |
| `Answer` | 參考答案，不送入檢索／重排序模型 |
| `Page`、`Evidence_Main_Section`、`Evidence_Sub_Section`、`Evidence_Note_Title` | 標註與核對資料；實際評分依報告的規則版本 |
| `Required_Numbers` 及相關標準欄位 | 新版必要數字評分，請沿用經確認的測試集格式 |

目前限制：上傳檔最多5 MB、Excel 解壓內容最多32 MB、最多1000題。實驗預設排除 ID `26、88、95、102、113`；用新題庫時若需這些題號，請維護者調整 `Code_2/config/evaluation.py`，不要把被排除視為檢索失敗。

題型分類、必要數字標準若沒有填好，不應把未知分類或不可評分題硬算為零分。建議由維護者先確認題庫格式，再做方法比較。

### 9.2 圖表與兩種分數

執行前可勾選產生圖表；未勾時可在結果旁事後製作，另存統計報告。

| 指標 | 代表什麼 |
| --- | --- |
| 原始分數 | 所需證據項目找齊的程度，最高10分 |
| 排名加權分數 | 找齊程度及正確證據出現的先後，最高10分 |
| TopK 曲線 | 只保留前K筆時，證據覆蓋與分數如何變化 |
| 回答正確率 | 需另外核對模型答案；不等於上述檢索分數 |

有 `Required_Numbers` 的新版題目以必要數字為準，允許不同 chunk 補齊；舊報告可能採章節／年度規則。比較時需使用相同題庫、評分版本、召回數及父項設定。

### 9.3 產生的檔案

| 檔案 | 適合誰看／做什麼 |
| --- | --- |
| `results.xlsx` | 使用者看逐題分數、方法比較、圖表用表格 |
| `result.json` | 保存完整結果，供程式還原與追查 |
| `ID_*.json` | 分題候選資料，可供後續重排序 |
| `ID_*.md` | 分題可讀證據，供閱讀或回答模型使用 |
| Markdown／圖表統計報告 | 解釋結果、記錄設定及查看圖表 |

各批次依操作保存在：

```text
Output/reponse_embedding/  # 檢索
Output/reponse_rerank/     # 重排序
Output/reponse_answer/     # 回答
```

目錄名稱 `reponse` 是目前程式使用的拼字，請保持不變。不要只保留 Excel 後刪除 JSON／來源 chunk，再期待完整還原舊實驗。

## 10. 用舊報告做重排序

1. 開啟「執行紀錄」，選擇可用的舊檢索報告。
2. 在「舊報告重排序」選擇 BGE 或 Voyage 設定。
3. 設定保留子項數（例如10），勾選題目後執行。

此功能沿用原候選，不重新檢索；會依來源及雜湊核對並還原候選全文，重排後再帶回必回父項。結果另存，原報告保留。來源 chunk 缺失或不相符時應先處理來源，不要把失敗當成重排低分。

## 11. 查看及刪除向量資料

在「向量資料庫」依模型、切法、索引與財報展開清單，查看 chunk 及其 metadata，也可套用篩選。

刪除時先勾選要處理的文件／群組，預覽受影響範圍，再確認刪除。一般文件刪除與整個損壞集合移除是不同操作；索引損壞時，能列出清冊不代表能正常讀取或刪除其中向量。

原始 PDF／chunk 檔與向量索引是不同資料。刪除索引中的財報不代表已刪除原始來源；反之，只刪來源檔也不會自動清掉已建的向量。

## 12. Google Colab 操作

直接開啟 [Colab Notebook](https://colab.research.google.com/github/Yusin0729/Financial-Report-Novice-Q-A-System-Tools/blob/main/colab/Financial_RAG_GPU.ipynb)。

1. 複製到自己的 Google Drive，選 GPU 執行階段。
2. 第一個程式格填入儲存庫網址，執行安裝。
3. 執行裝置／金鑰設定格，確認實際顯示 `cuda` 與 GPU 名稱。
4. 掛載 Drive，把所需資料複製到 Colab。
5. 選起訖階段、執行來源清單，再填 `SOURCE_IDS`。
6. 設定切法、字數、標籤、模型及索引名稱，執行工作。
7. 工作結束後執行最後的備份格，確認 Drive 已有備份 ZIP。

第一格填入：

```python
REPOSITORY = "https://github.com/Yusin0729/Financial-Report-Novice-Q-A-System-Tools"
BRANCH = "main"
DEVICE = "auto"
```

Drive 目錄範例：

```text
MyDrive/Financial_RAG_data/
  Financial Statements/        # 從階段1開始
  Output/
    markdown_raw/原批次/       # 從階段2開始
    markdown_processed/原批次/ # 從階段3開始
    markdown_tagged/原批次/    # 從階段4開始
    markdown_chunk/原批次/     # 從階段5開始
```

金鑰放 Colab 左側「密鑰」：`VOYAGE_API_KEY`、`GEMINI_API_KEY`、`OPENAI_API_KEY`，允許 Notebook 讀取。不要填入可分享的程式格。

`SOURCE_IDS` 使用上一格實際印出的 ID，例如：

```python
START_STAGE = 4
END_STAGE = 5
SOURCE_IDS = ["實際批次名稱/2024_2330_tagged.md"]
CHUNK_MODE = "parent_child"
CHUNK_SIZE = 250
BACKEND = "bge"
```

目前 Notebook 的查詢範例固定執行本機 BGE 重排序；完整 Gemini／GPT 回答與 Excel 批次介面請依本機網站操作，不能把此範例視為已包含全部網站功能。

Colab 的 `/content` 可能隨執行階段回收。運作中的 Chroma／題庫使用 Colab 本機磁碟，工作完成後備份到 Drive；不要直接把正在使用的 SQLite／Chroma 放在 Drive 上運作。

## 13. 常見問題

| 情況 | 先做什麼 |
| --- | --- |
| 雙擊網站後沒有開啟 | 看啟動視窗錯誤，確認兩個環境已安裝；再開 `http://127.0.0.1:8765/` |
| 網站顯示無法連線 | 確認後端仍在執行；先查工作狀態，避免重複送出同一批 |
| 來源檔案不在清單 | 確認階段、資料夾、檔名及批次結構，更新清單 |
| 找不到剛建立的索引 | 確認建庫成功、模型／切法正確，展開歷史索引 |
| 第一次執行很慢 | 可能正在下載模型或執行 PDF 表格辨識，先看當前進度 |
| Voyage／LLM 無法呼叫 | 確認用途、模型、key、帳號額度及必要 API 啟用選項 |
| Excel 顯示解壓過大 | 改存只包含需要欄列的新 `.xlsx`，避免整張表帶有大量多餘格式 |
| GPU 顯示 CPU | `auto` 沒偵測到 CUDA；確認實際分配 GPU 及 PyTorch 支援 |
| GPU 記憶體不足 | 先用批次1、單一工作，避免同時載入多個本機模型 |
| 向量索引損壞 | 先保存錯誤及來源資訊，由維護者確認修復／整組移除方式 |
| 找到章節但答錯數字 | 核對原表、年度欄、單位、所選證據與計算，不只看章節分數 |
| 舊報告無法重排序 | 確認完整來源 chunk JSON及雜湊相符；來源清理後可能無法還原 |

回報問題時提供：操作步驟、資料檔名、使用的索引／模型、錯誤文字及發生在哪個階段。不要附 API key。

## 14. 分享給別人與備份

- 分享程式：提供 GitHub 網址及這份說明，接收者自行安裝環境、設定金鑰。
- 分享資料：另外提供有權分享的 PDF、chunk 或完整索引副本，說明年度、股號及切分設定。
- 分享實驗：保留題庫版本、`result.json`、`results.xlsx`、分題檔與來源資訊。單看平均分數無法還原完整設定。
- 搬移環境：重新安裝 Python 環境；模型快取與資料可另行安排。跨 Windows／Linux 的 Chroma 還原尚待驗證。

不要把自己的 `.env`、API 設定檔或仍在寫入中的資料庫直接交給其他人。
